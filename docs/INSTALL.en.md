# Installation: your own Codex Mac and OpenClaw network

[中文](INSTALL.zh-CN.md) · [Workbook](WORKBOOK.md) · [Permission details](PERMISSIONS.en.md)

Version: **0.3.3**. Current collector/service support: **macOS**. A Linux VPS can host the Gateway. No maintainer account, Gateway or credential is required.

## Instructions for the OpenClaw agent

Read the whole guide before making changes. Identify the human-selected Mac node, its current OS user and Codex installation. Inspect existing installs/state before creating anything. Use `exec host=node node=<actual-node-id>` for Mac shell commands; use the Gateway host for Gateway administration and loading the reply Skill. Never assume the Gateway filesystem is the Mac filesystem.

Ask only for missing choices: target Mac, own Gateway WSS URL, Discord account/channel/owning agent, allowed human sender IDs, and the already-selected App UI provider if App replies are wanted. Do not ask the user to paste tokens/private keys into chat. Preserve existing node identity, CLI/session-host capabilities, unrelated configuration/Hooks and desktop drafts. Respect current node/tool/Discord policy; a refusal is not permission to use a different driver.

The stages below are separate: plugin/collector installed, operator authorized, notification destination enabled, reply Skill loaded, sender allowlist configured, and App permissions verified. Report incomplete stages honestly. If an existing collector belongs to another config, use that config or plan a state-preserving migration; do not install a second competing collector.

## 1. Prepare and connect the Codex Mac

On the Mac, verify Node.js (24.x 24.16+ or a supported 26.1+ runtime), npm, OpenClaw 2026.10.3+, and the user's own Codex installation/login:

```sh
node --version
npm --version
openclaw --version
codex --version
```

Install missing OpenClaw/Node prerequisites using the [official installer](https://docs.openclaw.ai/install), matching the Gateway's supported version. macOS service and permission behavior differ from Linux/Windows; this release does not install a collector on those OSes.

If the Mac is already paired and executable, reuse it. Otherwise, on **your Gateway**, generate a one-use join command:

```sh
openclaw devices join-code
```

Run the printed command on the **Mac**, using the version and private join URL generated by your Gateway. Keep `--service` for background operation. The generated command may include `--session-host`: keep it only when the owner wants this trusted Mac to host agent sessions. This notifier needs executable node access; session hosting is optional. Do not add `--all-commands` merely to avoid an approval. Join URLs are short-lived credentials and must stay out of public chat/logs.

On the Gateway, confirm the selected node is online and exposes `system.run`, using current node list/describe tools. Approve only the exact device/capability request under your existing policy. Do not start pairing again just because a later operator or App permission is missing. [Official node enrollment](https://docs.openclaw.ai/cli/connect).

## 2. Download and install the plugin on that Mac

Use a private staging directory on the **Mac** and download the pinned release:

```sh
umask 077
NOTIFY_DOWNLOAD_DIR="$(mktemp -d)"
cd "$NOTIFY_DOWNLOAD_DIR"
curl --fail --location --proto '=https' -o openclaw-codex-notify-0.3.3.tgz https://github.com/deletoe/openclaw-codex-notify/releases/download/v0.3.3/openclaw-codex-notify-0.3.3.tgz
curl --fail --location --proto '=https' -o SHA256SUMS https://github.com/deletoe/openclaw-codex-notify/releases/download/v0.3.3/SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing
tar -tzf openclaw-codex-notify-0.3.3.tgz
openclaw plugins install ./openclaw-codex-notify-0.3.3.tgz
openclaw codex-notify --help
```

Inspect the exact archive/source before trusting it. The checksum detects changes relative to the downloaded manifest; it is not a separate publisher signature. OpenClaw may ask for local-source trust and capability review. For this reviewed archive in an authorized noninteractive install, supported versions accept `--force --accept-capabilities`; those flags do not approve macOS grants or other tool policy.

This is a local execution plugin: ensure these commands operate on the target Mac's plugin installation. Installing the plugin on the VPS alone cannot collect Mac sessions.

## 3. Install the collector and review Codex Hooks

On the **Mac**, replace the example endpoint with the owner's real WSS URL:

```sh
openclaw codex-notify install --gateway wss://gateway.example.com:443
openclaw codex-notify install --gateway wss://gateway.example.com:443 --apply
```

The first command previews; `--apply` writes backups, private config, five Hook handlers and the LaunchAgent. Sending remains disabled. Default config/state: `~/.openclaw/codex-notify/`; service: `com.openclaw.codex-notify`. The installer returns the actual paths. For custom/existing state, put `--config /absolute/private/config.json` immediately after `codex-notify` on every command.

Use Codex's official `/hooks` UI to review/trust the added handlers. Reload the relevant Codex client if required; different Codex homes may need their own review. Never bypass Hook trust or overwrite unrelated Hooks. The collector covers the current user's local sessions across projects; other OS users/remote hosts are separate deployments.

## 4. Authorize this Mac's notification operator

Node pairing, operator permissions and macOS desktop permissions are different layers. On the **Mac**:

```sh
openclaw codex-notify pairing-request
```

Give its instructions, endpoint and private destination path to your Gateway administrator/agent. On **your Gateway**, generate setup JSON into a mode-600 file, using your endpoint:

```sh
umask 077
NOTIFY_PAIRING_DIR="$(mktemp -d)"
openclaw qr --public-url wss://gateway.example.com:443 --json > "$NOTIFY_PAIRING_DIR/pairing.json"
```

Create/use an actual private temporary directory first. Transfer this file to the Mac destination printed by `pairing-request` through an existing trusted node file-transfer path or SSH. Do not echo/base64 it into model-visible transcripts. Do not use `--limited`: this version requests `operator.read`, `operator.write` and **`operator.admin`** for cross-agent channel discovery. Admin is broad authority; review it as such.

On the **Mac**:

```sh
openclaw codex-notify pair --file ~/.openclaw/codex-notify/pairing.json
```

If it returns `PAIRING_REQUIRED`, verify the device/request/scopes and execute its exact `approvalCommand` on the **Gateway**. Then rerun `pair --file` on the Mac before setup credentials expire. An auth error without a request ID is not a confirmed pending request. Generate new setup credentials if expired; do not revoke or overwrite an existing node token to fix enrollment.

Verify reconnect without setup credentials:

```sh
openclaw codex-notify pair
```

After success delete only the temporary pairing files on both hosts. Retain private `operator.json` and SQLite state. The installer reuses an existing node's device identity when compatible; native OpenClaw storage drift fails rather than guessing/copying another computer's identity.

## 5. Choose Discord destination and authorized reply senders

On the **Mac**:

```sh
openclaw codex-notify channels --query codex
openclaw codex-notify target --channel-id YOUR_CHANNEL_ID --account YOUR_ACCOUNT_ID --agent YOUR_AGENT_ID
```

Verify the actual Discord server/channel/account/agent, including same-name channels. Directory lookup can span agents. The destination is saved with sending disabled. No new Discord bot is installed: your own Gateway must already handle that Discord account.

Safely merge this into the **private config returned by install**, filling real human Discord user IDs. New installations use an empty array, which refuses all reply senders until configured:

```json
{"replies":{"allowedSenderIds":["YOUR_HUMAN_DISCORD_USER_ID"]}}
```

Preserve all other fields; do not replace the whole configuration with this snippet. Existing Gateway sender/guild/channel/mention controls still apply. Optional private fields: `replies.cliBinary` (absolute CLI executable), `replies.readerBinary` (absolute compatible native read executable), `replies.cliTimeoutMs`. Discovery normally finds App-bundled Codex or a CLI in PATH; explicit paths help LaunchAgents with a restricted environment.

Then:

```sh
openclaw codex-notify enable
openclaw codex-notify status
```

Check reported health/state paths. The service must be running with healthy native scanning and Gateway configuration; do not print private records/credentials into Discord. A notification contains Codex result/source information, so select an appropriately private channel.

## 6. Load the reply Skill on the agent host

Read [the Skill](../skills/codex-notify-reply/SKILL.md). Copy the complete `codex-notify-reply` folder from this pinned release's `skills/` directory (or the standalone Skill archive) to the **actual Discord agent's workspace `skills/` directory** on its Gateway/agent host. Inspect existing content before replacing it. Do not assume the default workspace if multiple agents exist.

Use that OpenClaw version's normal Skill discovery/reload/next-turn mechanism and verify that the intended agent sees `codex-notify-reply`; `openclaw skills info codex-notify-reply --json` can help inspect discovery in the active context. A node-only Mac does not need `reply-skill --apply`, an extra Skill copy, or a node restart just to publish a Skill.

Confirm native human replies to the bot message actually reach this agent under current Discord mention policy. Do not globally relax mention, sender or tool rules. Native reply references and sender metadata are required; pasted IDs or quoted bot text are insufficient. Multi-Mac routing requires exactly one online node with a persisted match.

## 7. Prepare App permissions if App replies are wanted

CLI-origin replies need the native CLI and existing Codex authorization, not desktop control. App-origin replies need a separately authorized UI provider. The plugin is not a general desktop driver; the Skill orchestrates a provider already available to OpenClaw.

Prefer a signed OpenClaw.app/helper with stable identity, using **Dashboard → Settings → This Mac → Permissions** and its native Computer Control confirmation. Inspect the actual node's capability/permission report. A CLI node does not automatically become an App-backed control node.

For an already-selected JXA route, run through the **same Mac node executor used for real App operations**:

```sh
openclaw codex-notify permissions --backend jxa
openclaw codex-notify permissions --backend jxa --request --verify
# After the user changes settings, recheck:
openclaw codex-notify permissions --backend jxa --verify
```

Users may need to interact with macOS dialogs/settings and relaunch the responsible app. The probe requests Accessibility and System Events automation only as needed; it never types, clicks, switches sessions or sends a message. Pure AX/JXA does not request screen recording; a screenshot provider has its own requirements. Missing permissions return nonzero; `uiReadVerifiedForCurrentExecutor=true` proves only this read-only probe, not input or routing. Do not use a Terminal/Codex check as proof for the node. A denial stops this route and cannot be bypassed by changing tools. [Details](PERMISSIONS.en.md).

For a new install explicitly choosing JXA, `install --apply --app-permissions jxa` combines the request/probe after collector installation. Do not rerun install merely to recheck permissions.

## 8. Acceptance and handoff

Use an owner-approved disposable Codex session. After a result remains unhandled for the normal 20-minute window, verify a single reminder appears in the chosen channel. Do not shorten deadlines or reconfigure production state just for a demonstration.

Reply to that reminder using Discord's **native Reply**. The agent must resolve the exact Mac/home/thread, enforce sender policy and deduplication, re-read source/baseline, then use CLI only for confirmed CLI-origin sessions or authorized UI only for App-origin sessions. For App, verify main content title/project/recent context and preserve drafts before input. Unknown or busy/conflicting sessions stop.

Verify a matching new persisted user turn in the original session; separately report **delivery**, **plugin registration**, and **task status**. If native text differs only by one extra App LF, the narrow compatibility rule can register it. A failed `reply-confirm` after observed delivery permits registration recovery only, never retyping/restarting CLI. Reading a session alone does not cancel a pending reminder; actually handling/replying does.

Record the private deployment worksheet in [WORKBOOK.md](WORKBOOK.md). Code tests, a healthy collector or a read-only permission probe are not an end-to-end live acceptance result.

## Upgrade, stop and uninstall

Use the same config/state and preserve the SQLite outbox, reply deduplication and operator credential. Stop before upgrading the archive. Keep a backup outside the plugin directory, then review changed Hooks before restarting. Existing service/config mismatch requires deliberate migration, not a second collector.

```sh
openclaw codex-notify stop
# Install the reviewed new archive, then review any changed Hooks.
openclaw codex-notify start
openclaw codex-notify status
# Disable sending / remove collector (preview, then apply):
openclaw codex-notify disable
openclaw codex-notify uninstall
openclaw codex-notify uninstall --apply
openclaw plugins uninstall codex-notify
```

Uninstall the collector before deleting plugin code. Uninstall preserves private state/credentials for audit and deduplication; revoke Gateway grants separately when decommissioning a Mac. Use the official pairing and permission recovery flows for drift; never delete locks, edit TCC/native session databases or disable sandbox/approvals to force success.
